## Part 3:分類邏輯解釋

### 3.1 點解「危機介入偵測邏輯」要絕對保密?
唔止係商業考量——如果偵測邏輯完全公開,有心人可以研究點樣講嘢先唔會觸發
安全機制,呢個屬於安全設計原則(唔止IP保護),應該永遠唔公開具體偵測
關鍵詞/閾值,但「呢個機制存在,而且會做啲咩」呢個層面嘅資訊建議公開
(建立用戶信任)。

### 3.2 點解「協議」開放但「具體數值」保密?
呼應之前開放標準協議策略——協議(格式定義)冇代碼,冇「代管服務」風險;
具體數值先係你哋真正嘅心理學研究成果,亦都係MongoDB/Elastic嘅教訓話你知
唔可以隨便公開嘅嘢。

### 3.3 「上雲 vs 落地」嘅核心判斷原則
```
上雲(伺服器端運算)嘅原則:
  - 涉及你哋核心IP嘅運算邏輯(客戶睇唔到公式,只收到結果)
  - 需要持續更新/迭代嘅邏輯(伺服器端方便你哋隨時優化,唔使等客戶更新App)

落地(客戶端運算)嘅原則:
  - 純渲染/展示邏輯(冇核心IP,睇到代碼都冇用)
  - 需要即時反應、唔可以有網絡延遲嘅部分(例如眨眼、微掃視呢類每幀都要
    郁嘅動畫,如果次次都要問伺服器,反應會慢)
```

建議嘅具體切割:核心情緒/肌肉運算(每次劇本轉換先做一次)喺雲端,但
一旦攞到咗輸出結果(blendshape序列),之後嘅插值/播放(逐幀點樣喺
關鍵幀之間平滑過渡)可以喺客戶端做——呢個做法保護核心IP,同時保持即時
反應嘅使用體驗。

## Part 4:一句總結

```
公開嘅:協議格式、架構概念、基礎款渲染代碼、免費層8基礎情緒
保密嘅:所有具體數值(肌肉矩陣、心情公式、危機偵測邏輯)、進階演算法
賣嘅:核心運算引擎嘅使用權(API訂閱/整合授權),唔係賣代碼本身
雲端運算:核心IP相關嘅一次性運算(劇本轉表情決策)
客戶端運算:純展示/插值/即時反應嘅渲染部分
```
