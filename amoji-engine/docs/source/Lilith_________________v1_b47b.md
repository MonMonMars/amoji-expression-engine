# Lilith 系統架構:兩層數值系統 + 微表情心理學研究整合

## Part 1:正式定義「兩組數值」架構

你提出嘅呢個分層,其實正正係一個完整表情引擎必須要有嘅結構——**語意層**同**幾何層**分開,先可以做到「同一套情緒邏輯,套用到唔同角色/唔同臉部結構」。

### 數值組 A:情緒強度輸出值 (Emotion Intensity Value)
- **範圍**:0(中性)→ 1(人類生理極限)→ >1(動畫/機械人誇張)
- **本質**:呢個係「語意層」——一個抽象嘅情緒訊號,例如 `Happy: 0.6`、`Fear: 0.3`
- **用途**:呢個係你套系統嘅**輸入/決策層**——AI 判斷/選擇「而家應該表現咩情緒、幾強」,呢個數值本身唔知道臉部結構係點,淨係代表心理狀態強度

### 數值組 B:臉部動點座標值 (Facial Point Position Value)
- **範圍**:每個點位、每個方向(U/D/L/R)各自嘅位移量,例如 `MO-L: U 0.4 + L 0.3`
- **本質**:呢個係「幾何層」——實際幾十個點喺臉上郁去邊、郁幾多
- **用途**:呢個係你套系統嘅**輸出層**——真正驅動 3D 模型/2D 圖像/機械人伺服馬達嘅數值

### 兩組數值嘅關係:映射表 (Mapping Table)
```
數值組 A (情緒 + 強度)
        │
        ▼  透過「情緒對照表」(即我哋之前做嘅開心/憤怒/驚訝等表)
        │
數值組 B (57 個點位各自嘅方向 + 幅度)
```

**呢個分層設計嘅商業價值**:
1. **同一套數值組 A,可以映射去唔同嘅點位系統**——寫實 Lilith 用 57 點,卡通角色用 24 點,機械人可能得 12 點(伺服馬達有限),但輸入嗰個「Happy: 0.6」係共通嘅。呢個正正達成咗你最初講嘅「所有 AI 通用」嘅目標。
2. 客戶接入你套 SDK 嗰陣,佢哋淨係需要處理數值組 A(簡單、通用),數值組 B 嘅映射邏輯(你嘅專業知識、核心機密)可以留喺你嘅引擎入面,唔使開放——呢個就係你嘅護城河。

## Part 2:面部微表情心理學研究整合

### 2.1 微表情 vs 一般表情(巨表情)嘅本質分別
研究文獻對持續時間有唔同界定,但普遍共識係:

- **微表情 (Micro-expression)**:<cite index="17-1">持續時間少於 500 毫秒,通常好細微、好容易睇漏眼,而且經常只發生喺局部臉部區域,可能帶有不對稱性</cite>。亦有研究界定得更短:<cite index="18-1">一般持續 1/25 秒到 1/3 秒</cite>,亦有針對辨識能力嘅實驗<cite index="8-1">建議微表情嘅上限大約係 1/5 秒(即 200 毫秒)</cite>。
- **巨表情 (Macro-expression)**:一般表情,持續時間明顯長(通常 0.5 秒以上到數秒),即係我哋之前做嘅「微笑/燦笑/大笑」呢類會刻意展示、觀察者容易察覺嘅表情。

### 2.2 微表情嘅成因:「不自主洩漏」
微表情唔係設計出嚟展示俾人睇嘅,而係<cite index="16-1">當人試圖隱藏或壓抑真實感受時,產生嘅一種「洩漏」</cite>。心理學上有個生動嘅解釋:<cite index="14-1">當一個人有真實情緒但想隱藏,不自主嘅神經通路會先啟動,產生真實表情;短短幾毫秒之後,自主嘅神經通路先接手,用一個受控制、社交上恰當嘅表情蓋過去——結果就係一閃即逝嘅「真相」先於「面具」出現。</cite>

### 2.3 關鍵訊號一:不對稱同「局部臉部」——唔係成張臉一齊郁
呢個係好重要嘅一個修正,同大眾對微表情嘅刻板印象唔同:<cite index="10-1">真正嘅情緒洩漏,好多時唔係一閃而過嘅「教科書式」完整微表情,而係不一致、唔對稱、或者情境上唔協調嘅局部動作——研究者觀察到,大部分「不一致情緒閃現」通常只顯示喺上半臉或者下半臉其中一邊,唔會成張臉一齊反應。</cite>

**對你套系統嘅意義**:呢個直接證實咗你已經用開嘅「不對稱」設計邏輯(懷疑/尷尬嘅單邊動作)唔止係美學選擇,而係有心理學根據——真實嘅情緒洩漏本來就傾向不對稱、局部。

### 2.4 關鍵訊號二:情緒強度影響洩漏程度
<cite index="9-1">高強度情緒喺欺瞞/掩飾狀態下,比低強度情緒明顯更容易洩漏。研究發現參與者喺 98.3% 嘗試掩飾真實感受嘅情況下,都出現咗情緒洩漏,當中恐懼類表情嘅洩漏發生率最高,開心類最低。</cite>另一項研究補充:<cite index="15-1">高強度情緒喺「情緒中和(neutralize)」嘗試下,較難掩飾,特別容易喺上半臉洩漏;恐懼洩漏最多,開心洩漏最少。</cite>

**對你套系統嘅意義**:你嘅數值組 A 已經有強度數值(0-1)——依家可以加一條規則:**強度越高嘅「被壓抑情緒」,洩漏機率/幅度越大**,而且優先喺上半臉(眉毛、眼部)出現,呢個可以直接寫成演算法邏輯。

### 2.5 關鍵訊號三:眼部 vs 嘴部——遮蓋方向唔對等
呢個發現對動畫時序好有實際操作價值:<cite index="11-1">研究發現一個人可以用嘴部動作(例如笑)回溯性咁遮蓋番眼部先出現嘅微表情訊號——但呢個遮蓋效果只喺「先眼後口」嘅方向先生效,如果順序反轉(先口後眼)就唔會產生遮蓋效果。</cite>

**對你套系統嘅意義**:如果你想做「假笑蓋過真實情緒」呢類細膩效果,時序必須係:眼部先閃現真實情緒(短暫、不對稱)→ 然後嘴部動作(展示笑容)接上,先會令觀眾/AI 判斷系統覺得「呢個係一個掩飾行為」而唔係「單純混亂嘅表情」。

## Part 3:整合方案——加入「第三個維度」到你套系統

依家你套系統其實有三層,唔止兩層數值,建議正式命名:

| 層級 | 名稱 | 內容 | 對應你嘅講法 |
|---|---|---|---|
| Layer 1 | 情緒強度值 | 0 → 1 → >1 | 「情緒輸出數字」 |
| Layer 2 | 臉部點位值 | 每點 U/D/L/R + 幅度 | 「臉部顯示點位數字」 |
| Layer 3(新增) | 時間/真實度層 | 持續時間 + 對稱性 | 未命名,今次新加 |

### Layer 3 建議規格

| 參數 | 定義 | 數值範圍 |
|---|---|---|
| Duration(持續時間) | 表情由 0 升到峰值、再回落到 0 嘅總時長 | 微表情:0.04–0.5 秒;巨表情:0.5–4 秒 |
| Symmetry(對稱度) | 左右兩側幅度差異 | 0 = 完全對稱;1 = 完全單側(呢個唔係新點位,而係修改 Layer 2 輸出時,左右套用唔同倍率) |
| Region Lock(區域鎖定) | 洩漏是否只限上半臉或下半臉 | Upper-only / Lower-only / Full |
| Suppression Overlay(壓抑疊加) | 表層情緒(展示俾人睇嗰個)+ 底層情緒(真實但被壓抑嗰個)| 兩組 Layer 1 數值疊加,底層用短 Duration + 高 Symmetry 差異 + Region Lock 表現 |

### 實際運作例子:「Lilith 表面開心,但其實尷尬」
1. 表層(Macro):Happy 0.5,Duration 2 秒,Symmetry 0(對稱)——呢個係觀眾主要睇到嘅
2. 底層洩漏(Micro):Embarrassed 0.6,Duration 0.15 秒,Region Lock = Upper-only(只喺眉毛、眼部出現),時序上喺 Happy 嘅嘴部動作**之前**閃現(對應 2.5 嘅「先眼後口」原則)
3. 輸出結果:一個表面自然咁笑緊、但眼神/眉毛喺笑容出現前 0.15 秒閃過一絲不安嘅角色——呢個係現時市面上絕大部分 AI 表情系統做唔到嘅細膩度
