# Amoji 系統規格 —— Part VV:角色原型適配層(Layer CA)—— 由人類擴展到任何物種/物件

## 核心原則:Layer 1 已經係通用嘅,缺嘅係「翻譯層」

你哋成套系統一直堅持「Layer 1(抽象情緒強度值)獨立於 Layer 2(具體渲染)」——今次
擴展嘅邏輯完全一致:Layer 1 輸出(valence/arousal/情緒標籤)本身冇物種之分,
缺嘅係一個將呢啲抽象值,翻譯做「呢個物種/物件實際擁有邊啲表達器官」嘅適配層。

### ⭐ 補充核心設計原則:Amoji 嘅本質係一套「擬人化引擎」
所有非人類原型,都係將人類可以理解嘅情緒語言,投射去唔同嘅表達媒介度——呢個唔係
缺點,而係任何俾人類觀眾睇嘅角色設計都必須做嘅事(觀眾永遠係人)。但唔同原型嘅
擬人化程度唔一樣:

| 原型 | 擬人化嘅嘢係咩 | 表達渠道本身 |
|---|---|---|
| 動物 | 情緒**詮釋**(人類詞彙套喺動物訊號度) | **真實**——尾巴/耳朵訊號有真正嘅動物行為學根據 |
| 擬人化物件 | 情緒**表達渠道本身**(檯燈冇情感,但賦予咗表演意圖) | **虛構**——物件本身冇任何天然情緒訊號 |
| 外星生物 | 兩者都係(冇現實對應可以參考) | 完全設計者自訂 |

**呢個分別喺實作上好重要**:動物原型嘅表達渠道設計,必須有真實行為學研究支持
(唔可以亂噏,錯咗會顯得唔準確/失禮),因為底層有真實生理訊號撐住;物件/外星
生物原型就完全係表演藝術嘅創作決定,冇「啱唔啱」,淨係有「有冇效果」。呢個亦都
解釋咗點解你哋一直以嚟嘅心理學/FACS研究咁重要——呢啲研究本身就係「人類點樣
理解情緒」嘅知識庫,先係擬人化嘅真正原材料。

```
Layer 1(通用情緒輸出,物種無關)
        |
Layer CA(角色原型適配器)——決定「呢個角色有咩表達渠道」
        |
Layer 2(具體點位/渲染)——只喺呢個原型嘅實際渠道上運作
```

## Part 2:動物原型(四足哺乳類,例如貓狗)

### 2.1 研究基礎——耳朵、尾巴、身體姿態係三個獨立表達渠道
<cite index="8-1">寵物用姿態、面部表情、尾巴同耳朵動作、同其他細微線索嚟溝通感受——動物冇
太多語言線索,非語言溝通因此更加重要。貓嘅細微線索(耳朵位置、尾尖、眼形)尤其重要。</cite>
<cite index="8-1">狗傾向透過尾巴、身體姿態、嘴部,較外顯咁展示意圖;貓就較含蓄,可能會迴避
而唔係外顯展示情緒。</cite>

### 2.2 尾巴——一個人類完全冇嘅獨立表達渠道
<cite index="11-1">搖尾巴唔一定代表開心——最基本嚟講,搖尾巴代表想互動嘅意圖。</cite>
<cite index="10-1">尾巴舉高:自信、開心、友善。尾巴夾低或者收喺兩腿之間:恐懼或者順從。
尾巴膨脹:警戒,想令自己顯得大隻嚟應對威脅。尾巴甩動/抽動:煩躁或者過度刺激。</cite>
<cite index="13-1">高、僵硬嘅尾巴:警戒、自信、可能帶支配性,如果配合其他緊張身體語言,
甚至可能具攻擊性。</cite>

### 2.3 耳朵——同樣獨立於人類表情系統
<cite index="16-1">向前:耳朵豎起或者向前傾,表示專注同高度警覺。</cite><cite index="10-1">
向後拉平:恐懼、順從、或者安撫;配合低伏嘅身體,代表唔舒服。</cite>

### 2.4 貓獨有嘅組合訊號(多渠道同時判讀)
<cite index="10-1">耳朵向前 + 尾巴豎起 + 慢眨眼 = 放鬆、友善嘅貓;耳朵夾實 + 瞳孔放大 +
尾巴亂甩 = 躁動——係時候俾佢啲空間。</cite><cite index="10-1">慢眨眼係信任同感情嘅訊號——
你嘅貓朋友噉樣講「我覺得同你喺埋一齊好安全」。</cite>

### 2.5 動物原型嘅 Layer CA 定義

```
CharacterArchetype: QuadrupedMammal
可用渠道:
  - earPosition(前傾/中性/後拉,取代人類眉毛嘅部分功能)
  - tailPosition(高/中/低/夾尾)
  - tailMotion(靜止/慢搖/急甩/膨脹)
  - bodyPosture(挺立/伏低/拱背)
  - eyeState(慢眨眼=信任、瞳孔放大=興奮或恐懼、直視=挑戰)
  - muzzleTension(取代人類嘴角,但幅度細好多、冇「微笑」概念)
情緒映射示例:
  - 開心/放鬆 → earPosition前傾, tailPosition高, eyeState慢眨眼
  - 恐懼 → earPosition後拉, tailPosition夾尾, bodyPosture伏低
  - 警戒/懷疑 → earPosition前傾但緊張, tailMotion急甩, eyeState瞳孔放大
```

⚠️ 重要設計原則:動物冇「微笑」——唔可以將人類嘅嘴角上揚公式直接套用去動物角色,
呢個會顯得怪異同唔準確。動物嘅「開心」主要透過耳朵/尾巴/眼神表達,嘴部改動幅度應該
大幅收窄或者移除。

## Part 3:鳥類原型
延伸邏輯:羽毛蓬鬆度(取代表情肌肉嘅部分功能,例如受驚嗰陣羽毛貼實縮小身形,
放鬆嗰陣蓬鬆)、頭部傾側角度(鳥類特別依賴頭部傾側嚟改變視角,因為眼睛喺頭側)、
翼位置(收攏/半張=情緒指標)。呢部分建議日後有實際需求先深入研究,原則同動物
原型一致:每種物種都要獨立搵返佢自己獨有嘅表達渠道,唔可以將人類公式硬套。

## Part 4:外星生物/奇幻生物原型(設計彈性最大)

### 4.1 核心原則:通用情緒理論 + 設計自由度
外星生物冇現實對應可以研究,建議做法:
1. 保留 Layer 1 嘅通用情緒邏輯(valence/arousal 依然適用,呢個係心理學層面嘅
抽象概念,唔限定於人類生理)
2. 表達渠道完全由設計師自定義——例如三隻眼嘅生物,可以三隻眼獨立控制,或者
觸手類生物,觸手嘅捲曲程度可以做情緒指標
3. 建議保留少量「人類可辨識」嘅錨點(例如如果生物有眼睛概念,瞳孔放大邏輯
仍然可以沿用眼球錨點研究——瞳孔反應係少數幾個跨物種都有科學基礎嘅生理指標)

### 4.2 Layer CA 定義範本

```
CharacterArchetype: CustomAlien
設計師自訂渠道(範本):
  - primaryFeature1至N(自由定義,例如觸手數量/顏色變化/發光強度)
  - 建議保留:pupilDilation(如果有類眼睛結構,沿用人類研究)
情緒映射:完全由設計師決定,但建議保持「強度值單調遞增」原則
(intensity越高,無論邊個渠道,變化幅度都應該越大——呢個係跨所有原型嘅通用規則)
```

## Part 5:擬人化物件原型(「kitchenware」——茶煲/檯燈/汽車呢類)

### 5.1 業界公認原則:用物件本身固有嘅可動部件表達情緒,唔好強加人類五官
呢個係動畫業界一個歷史悠久嘅原則(Pixar 早期短片《Luxo Jr.》確立咗呢個手法):
唔好將人類五官硬貼喺物件度,而係搵返物件本身已經有嘅可動結構,將呢啲結構
賦予表演意圖——例如檯燈嘅頸部彎曲角度、汽車嘅頭燈開合、茶煲嘅壺嘴角度。

### 5.2 Layer CA 定義範本

```
CharacterArchetype: AnimatedObject(以檯燈為例)
可用渠道(全部嚟自物件本身固有結構):
  - neckBendAngle(頸部彎曲,取代人類頭部傾斜)
  - headTiltAngle(燈罩角度,取代人類頭部俯仰)
  - lightIntensity/flicker(燈光強弱/閃爍,取代人類嘅眼神/表情強度)
  - baseWobble(底座輕微搖晃,取代人類嘅身體語言)
情緒映射示例:
  - 開心/興奮 → neckBendAngle活潑彈動, lightIntensity提升,無閃爍
  - 傷心 → neckBendAngle下垂, lightIntensity調暗
  - 恐懼/驚訝 → lightIntensity瞬間閃爍, neckBendAngle急速後縮
```

呢個原型嘅通用設計法則:先盤點「呢件物件現實中有邊啲部件係可以郁動嘅」,
先至決定表達渠道——唔可以問「呢件物件應該有咩表情」,而係問「呢件物件本身
有咩郁動能力,可以點樣賦予表演意圖」。

## Part 6:機械人/機械原型(已有大量研究)
```

可用渠道:直接對應伺服馬達/驅動器(有限自由度,受硬件規格限制)
特殊考量:

    明顯人工,黎令「風格」訊號清晰一致
```

## Part 7:總覽——Layer CA 嘅通用架構原則

```
每個 CharacterArchetype 必須定義:
1. availableChannels[] —— 呢個原型實際擁有嘅表達渠道清單
2. channelMapping(layer1Output) → channelValues —— 情緒轉渠道嘅映射函數
3. forbiddenChannels[] —— 明確排除嘅渠道(例如動物原型必須排除「嘴角微笑」)
4. universalRules —— 跨原型都適用嘅規則(例如強度值單調遞增、瞳孔反應如適用)

Layer 2 渲染器只需要問 Layer CA:「呢個原型有邊啲渠道?」,唔使自己判斷
「呢個物種應該點表達情緒」——呢個判斷責任全部落喺 Layer CA 嘅定義度。
```

呢個設計令 Amoji 引擎真正做到「一套後端,適配任何角色類型」——同十級表情
呈現系統(同一Layer 1,插唔同Surface Renderer)係同一個架構哲學,而家加多
一個維度(物種/物件原型),同「寫實度級數」呢個維度完全正交、可以自由組合
(例如「Level 4 anime風格嘅貓」、「Level 9 寫實嘅機械人」)。
