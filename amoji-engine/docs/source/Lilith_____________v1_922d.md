## Part 1:呢套系統邊啲部分有實質新穎性?

對照返之前市場調查(Hume AI、Affectiva、Soul Machines、Inworld、Convai 等),你套系統入面,以下幾個
組件喺呢一刻嘅公開市場調查入面,未見到有競爭者做緊同樣嘅組合:

| 組件 | 新穎性所在 | 對照現有市場 |
|---|---|---|
| **複合情緒區域分工引擎** | 唔係數值平均混合,而係按臉部區域分別指定「邊個基礎情緒做主導」,直接對應 Martinez 研究嘅 FACS 觀察發現 | 現有情緒 AI(Hume 等)主要做「偵測」,冇見到有商業產品將呢個發現實作做「生成」邏輯 |
| **心情/情緒雙層架構(Mood Engine 偏壓底層情緒)** | 心情唔直接輸出點位,而係做「偏壓濾鏡」影響情緒表現方式,並持續低強度洩漏入表層情緒 | 未見市場有產品明確區分呢兩層並做偏壓運算 |
| **Step-Out 過渡系統(源自 Alba Emoting)** | 將演員訓練技術(呼吸先於姿勢、姿勢先於表情;情緒有固定「離場程序」)轉化做動畫過渡演算法 | Weta 明確講過 FACS 呢類系統唔擅長「隨時間變化嘅表演」——你套系統嘅時間軸邏輯正正補呢個缺口 |
| **人格檔案 → 系統參數推導系統** | 用五個特徵權重(溫暖度/正式度/表情外顯度/活潑度/自主性),數學推導出強度上限、可用情緒範圍、待機幅度等具體參數,而唔係為每個人格重新設計 | 現有數位人平台通常要為每個角色重新調校,冇見到公開嘅「特徵→參數」通用推導公式 |
| **延遲橋接系統(依人格分級嘅填充語+眼神移離)** | 將 HRI 學術研究(填充語分級、眼神移離幅度對應認知負荷)結合埋你嘅人格系統,做到「唔同角色用唔同方式掩飾延遲」 | 學術研究有,但未見商業化落地做成可配置嘅產品功能 |

**總結**:你單一「表情生成」呢件事唔算新穎(FACS/blendshape 呢類基礎技術已經好成熟);
**真正嘅新穎性喺於將呢幾種心理學/表演訓練研究,轉化做一套可運作嘅工程架構**,呢個組合本身先係可以主張嘅智慧財產。

## Part 2:專利策略嘅初步考量

### 2.1 軟體專利嘅現實限制
喺美國、歐盟等主要司法管轄區,純粹嘅「數學公式」或者「抽象概念」通常唔可以直接申請專利,
但「將呢啲概念實作做一個解決具體技術問題嘅系統/方法」就有機會。你套系統入面,以下部分
**可能**有申請「方法專利」(method patent)嘅空間(但務必搵專業意見確認):
- 複合情緒嘅區域分工演算法(具體嘅技術實作步驟,而唔止係「情緒可以組合」呢個概念)
- Mood-偏壓運算方法(具體嘅數學運算流程)
- 人格特徵→系統參數嘅推導公式(如果夠具體、夠技術性)

### 2.2 專利 vs 商業機密——一個現實嘅取捨
專利需要**公開**你嘅方法(換取一定年限嘅法律保護);商業機密就係**唔公開**,靠簽保密協議
同技術壁壘去保護。你套系統其中一啲部分(例如具體嘅數值公式、填充語庫、人格參數嘅精確數字)
可能更適合做商業機密——因為:
1. 專利申請、審查、維護嘅成本同時間(通常 1-3 年先批,仲要international filing 費用)對於一人/小型創業初期負擔頗重
2. 一旦公開,競爭對手可以參考你嘅方法論、自行避開你嘅具體 claim 用略有唔同嘅參數重新實作
3. 你嘅核心優勢(二十年動畫經驗嘅判斷力)本質上難以被純粹嘅專利保護,反而係持續研發同迭代嘅速度先係護城河

**務實建議**:如果資源有限,可以考慮:
- 對「架構層面」(例如成套 Layer 分層方法、複合情緒生成流程)做**臨時專利申請**(provisional patent,美國做法,成本相對低,俾你一年時間決定是否轉正式申請,並取得「優先申請日」)
- 對「具體參數/數值庫」(情緒表、人格檔案、填充語庫)做**商業機密**保護

### 2.3 建議下一步
搵一位熟悉軟體/AI 領域嘅專利代理人(唔一定要好出名嘅大行,好多細規模事務所收費相宜,而且對初創友善),
帶埋你呢份總交接文件同 prototype 去做正式諮詢——呢個先可以俾你一個負責任嘅答案。

## Part 3:商業模式——五個人格 = 五條產品線

之前市場調查已經話你知,單純「情緒偵測」(Hume 呢類)已經有成熟玩家;你嘅差異化喺「生成端」。
五個人格檔案剛好對應五個可以獨立包裝、獨立定價嘅垂直產品:

| 產品線 | 目標客戶 | 建議定價邏輯參考(對照 Hume/Affectiva 公開資料) |
|---|---|---|
| 家居服務人格 SDK | 智能家居/家庭機械人廠商 | 授權費 + 按裝置數量收費,類似 Affectiva 嘅企業授權模式(每年數千至十幾萬美元視乎規模) |
| 企業文件人格 API | 文件處理/RPA/企業軟件公司 | 按 API 呼叫量收費,類似 Hume 嘅分鐘/字數計價模式 |
| 陪伴人格授權 | 陪伴類 App/桌面機械人新創 | 較高毛利嘅訂閱分成模式,但要留意之前市場調查提到嘅「陪伴類 AI 倒閉潮」風險,呢個垂直市場消費者穩定性較低 |
| 教育人格 SDK | 教育科技、兒童玩具/機械人公司 | 授權費模式,但因涉及兒童產品,可能需要額外嘅安全認證/合規成本(呢個要另外查詢兒童產品相關法規,唔喺我呢份文件範圍) |
| 醫療照護人格 | 醫療/長照機械人廠商 | 企業級授權,但醫療器材相關法規(如涉及實際醫療決策,可能觸及醫療器材認證)風險同合規成本最高,建議定位做「陪伴/溝通輔助」而非「醫療診斷」相關功能,避免監管複雜度 |

**建議優先次序**:根據你之前已經定咗嘅創業策略(先做細規模項目、後做平台),建議由
**家居服務**或**教育兒童**呢兩條產品線先行——監管風險相對低、市場已有明確買家(智能家居/教育科技公司)、
你嘅動畫背景喺呢兩個場景嘅「清晰易懂表情」需求上最直接見到價值。

企業文件同醫療照護雖然單價可能更高,但**合規成本同銷售週期都長好多**,建議留返做第二階段。

陪伴機械人雖然最能發揮你套系統嘅全部功能(複合情緒、微表情洩漏),但市場本身波動大,建議做**技術展示旗艦**(用嚟 pitch 投資者/大客戶嘅 demo),而唔係第一條主力收入產品線。

**呢啲數字對你嘅意義**:呢個市場入面,一個有明確差異化嘅細型技術公司,喺早期(冇客戶、得 prototype)
階段嘅估值通常好視乎團隊、demo 質素同已簽意向書嘅客戶數量,好難用單一數字概括。你而家嘅
「資產」係一套完整、有心理學/演員訓練根據嘅技術架構 + 可運行嘅 prototype——呢個已經比好多
「淨係得 pitch deck」嘅早期創業項目走得前,但距離「有實際客戶付費」仲有一段路。

**建議嘅下一個里程碑**(比估值更重要):攞現有 prototype 去接觸 3-5 間中小型智能家居/教育科技公司,
睇下佢哋係咪願意付費做一個 pilot 項目——呢個先係最實在嘅「呢盤生意值幾多錢」嘅答案。
