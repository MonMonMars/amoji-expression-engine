# Amoji 系統規格 —— Part U:共同發音(Coarticulation)與主導函數模型
## 口型系統嘅深化——由「離散口型」升級做「連續時間混合」

## 開場說明
搵唔到 Pixar 直接公開發表嘅口型技術論文——呢個好正常,大型動畫片場嘅內部 pipeline 屬於
商業機密,好少會完整公開。但搵到咗**幾乎全個業界(學術界、遊戲、動畫)都共同引用嘅源頭
研究**——呢個先係更有價值嘅發現,因為呢個係業界事實標準嘅理論根基,唔理邊間片場,內部
系統好大機會都係呢個模型嘅變種或者延伸。

## Part 1:Cohen & Massaro(1993)——奠基性嘅「主導函數」模型

### 1.1 核心概念:口型唔係「換畫格」,而係「持續嘅影響力曲線」
呢個係最關鍵嘅概念轉變:<cite index="71-1">Cohen 同 Massaro 描述咗實現 Löfqvist(1990)手勢理論嘅
視覺語音合成做法。</cite><cite index="68-1">佢哋提出每個音素都有一組「主導函數」(dominance functions)——
每一個發音器官(嘴唇、下顎、軟顎、喉、脷)都各自有一條獨立嘅主導函數,因為唔同發音器官
受相鄰音素影響嘅程度唔一樣。呢啲主導函數用負指數函數嚟表達,形狀有升有落。</cite>

**呢個直接大幅深化咗你之前 JALI 嘅 Jaw/Lip 二分法**——原來唔止「下顎」同「嘴唇」係獨立
系統,**軟顎、喉、脷都各自可以有獨立嘅主導函數**。你現階段系統可以先保留 jaw/lip 兩軌,
但呢個發現值得記錄低,方便日後擴充。

### 1.2 具體例子:「stew」入面嘅 U 音,點解會提早現形
呢個係一個絕佳、可以直接理解嘅英文例子:<cite index="65-1">喺 "stew" 呢個詞入面,"u" 呢個音節嘅
主導程度高過 "s" 同 "t";而且 "u" 有一個低嘅「預期速率」(anticipatory rate),呢個令佢嘅
主導力提早喺時間軸上發揮作用——結果就係,嘴唇嘟起(嘟嘴)嘅動作,會喺你實際聽到「u」呢個
音之前就已經出現。</cite>

**即係話**:講「stew」呢個字,個嘴唇喺你講緊「s」「t」嗰陣已經開始準備嘟嘴,因為個「u」
音嘅主導函數上升得早——**個嘴預先「劇透」咗即將要講嘅音**。

### 1.3 另一個經典例子:「sea」vs「sue」入面嘅「s」唔係同一個口型
<cite index="72-1">/s/ 呢個音嘅口型,喺「sue」(su)入面會比喺「sea」(si)入面有更多嘴唇圓展——
呢個係因為預期緊後面即將出現嘅圓唇母音(anticipatory coarticulation)所導致。</cite>

**對你套系統嘅意義**:呢個直接推翻咗「一個音素固定對應一個口型」呢個簡化假設——**同一個
「s」音,會因應後面即將出現嘅音,而有唔同嘅視覺形狀**。你之前 Preston Blair 10 口型表
(文件16)本質上係一個「多對一」簡化(將好多音素歸類做少數幾個口型),而家嘅發現話你知,
更精確嘅系統應該係「多對多」:<cite index="64-1">要準確噉將音素映射去口型,由於共同發音效應,
應該係多對多嘅映射,而唔係簡單嘅一對一。</cite>

### 1.4 兩種共同發音方向:預期性 vs 延續性
<cite index="72-1">共同發音嘅視覺影響分兩種:預期效應(anticipatory)——即將出現嘅音節改變咗
目前嘅嘴唇位置;延續效應(carryover)——之前嘅音節持續影響緊之後嘅音節,導致發音軌跡出現
明顯變化。</cite>

## Part 2:呢個模型喺業界嘅實際採用程度
呢個唔係一個過時或者小眾嘅學術理論——<cite index="66-1">Cohen 同 Massaro(1993)提出將相鄰口型
之間嘅過渡,模擬做上升同下降嘅負指數函數重疊(即係主導函數),呢個做法之後仲被多個後續
研究採納。</cite><cite index="67-1">呢個模型雖然通用同高效,但需要人手逐個測試對象、逐個調較先可以
攞到岩嘅共同發音參數。</cite>Massaro 同 Cohen 仲攞呢個模型做咗一個實際應用:<cite index="72-1">
喺加州大學聖塔克魯茲分校,Massaro 同 Cohen 創造咗 Baldi——一個 3D 動畫講嘢頭像,將音素
映射去 14 個口型,用嚟做共同發音視覺語音合成,證實可以提升視聽同步呈現嘅清晰度。</cite>

## Part 3:業界動畫師嘅實務智慧(補充理論)

### 3.1 唔好每個音都平等咁畫——呢個係新手最常犯嘅錯
呢個係一個好重要嘅實務原則,直接對應主導函數「有啲音主導力高、有啲音主導力低」呢個概念:
<cite index="62-1">如果將一個詞或者句子入面嘅每一個音都逐一標示出嚟做口型動畫,會令個嘴好忙亂、
過度animate;相反,如果考慮得太少,每個字嘅口型都用同等強度表達,就會令個嘴顯得瘋狂、
令觀眾混亂、睇得攰,結果就係動畫做唔到自然嘅臉部效果。</cite>

### 3.2 業界動畫師實際工作流程(教學機構訪談,師承 Pixar/Disney/DreamWorks 動畫師)
<cite index="60-1">先用真人參考(錄低自己講嗰句對白),先由「下顎」開始擋出動畫——喺母音嗰度落
key,喺輔音嗰度閉合;特別注意 M、B、P 呢類音嘅嘴唇接觸同壓緊;之後先加返「嘴唇/嘴角」形狀
嘅細節、加返渡幀令過渡更加順滑。特別提提:唔好俾牙齒呃咗——有時嘴唇會郁但下顎其實冇點郁,
兩者會重疊但唔一定同步。</cite>

**對你套系統嘅意義**:呢個確認咗你文件16已經做嘅「jaw/lip 分軌」係業界標準工作流程,
唔係你自己諗出嚟嘅簡化——真正嘅動畫師都係咁分開處理。

## Part 4:整合方案——升級 Layer V(由離散snapshot做連續主導函數混合)

### 4.1 新舊架構對比

**舊架構(文件15、16)**:逐字/逐音素跳去對應嘅口型,用 LOCKED/CLAMPED/OPEN 三態決定
情緒可唔可以疊加——呢個做法簡單、容易實作,但每個口型之間係「跳」過去嘅,冇考慮到相鄰
音素嘅提前/延後影響。

**新架構(呢份文件)**:每個音素喺 jaw、lip 兩條軌,各自有一條主導函數(negative exponential
上升+下降曲線),多個相鄰音素嘅主導函數會**重疊**——最終畫面嘅口型,係當前時間點上,所有
仍然有非零主導力嘅音素,按各自主導力加權混合出嚟嘅結果。

### 4.2 偽代碼

```javascript
function dominanceFunction(phoneme, articulator, t_relative) {
  // t_relative: 相對於呢個音素標準發音時間點嘅時間差(可正可負)
  const params = PHONEME_DOMINANCE_TABLE[phoneme][articulator];
  // params: { peakMagnitude, anticipatoryRate, carryoverRate }
  if (t_relative < 0) {
    // 預期階段(呢個音之前)
    return params.peakMagnitude * Math.exp(params.anticipatoryRate * t_relative);
  } else {
    // 延續階段(呢個音之後)
    return params.peakMagnitude * Math.exp(-params.carryoverRate * t_relative);
  }
}

function resolveMouthAtTime(phonemeSequence, t, articulator) {
  let weightedSum = 0, totalWeight = 0;
  for (const {phoneme, onsetTime} of phonemeSequence) {
    const w = dominanceFunction(phoneme, articulator, t - onsetTime);
    if (w > 0.01) {
      weightedSum += w * PHONEME_TARGET_SHAPE[phoneme][articulator];
      totalWeight += w;
    }
  }
  return weightedSum / totalWeight; // 加權平均 = 呢一刻嘅實際口型
}
```

**關鍵參數表(每個音素,每個articulator 都要有)**:
| 音素類別 | peakMagnitude(主導力峰值) | anticipatoryRate(預期速率,越低代表提早現形越多) | carryoverRate(延續速率) |
|---|---|---|---|
| 高主導元音(如 /u/, /o/) | 高 | 低(提早出現) | 中 |
| 弱主導元音(如 schwa 弱化音) | 低 | 高 | 高 |
| 雙唇音(/m/,/b/,/p/) | 極高(唇部)| 中 | 中 |
| 齒擦音(/s/,/z/) | 中(唇部形狀受後接元音影響大) | 視乎後接元音 | 低 |

**⚠️ 同之前 LOCKED 機制嘅關係**:雙唇音(MBP)嘅「必須完全閉合」呢個要求依然保留,但而家
理解做「呢個音喺 lip articulator 上有極高嘅 peakMagnitude,主導力大到可以完全壓過其他
重疊緊嘅音素/情緒訊號」,而唔係一個獨立嘅「hard override」規則——兩個機制殊途同歸,但
主導函數版本更加統一、更加符合真實語音學。

### 4.3 情緒疊加點樣同主導函數共存
情緒(Layer 1)可以理解做一個「持續、低頻率」嘅額外主導函數,疊加喺所有音素嘅主導函數
之上——但因為情緒嘅 peakMagnitude 通常遠低過強勢音素(例如 MBP),所以自然會被壓過,
唔使好似之前咁要手動寫「情緒容許權重」表——呢個係一個更優雅、統一嘅數學模型。

## Part 5:實作建議
呢個主導函數模型比之前嘅離散版本複雜好多,建議分階段:
1. **短期**:保留而家嘅 LOCKED/CLAMPED/OPEN 離散系統(文件16)——足夠應付 MVP
2. **中期**:針對最常見嘅共同發音案例(例如你套系統常用嘅詞彙入面出現嘅 /s/+圓唇母音
組合),手動加返「提前主導」規則,唔使做齊成套通用主導函數引擎
3. **長期**:如果要做到電影級精緻度,先投資做完整嘅主導函數引擎——呢個工作量大,建議
用返你之前 3D 技術路線入面提到嘅分階段策略嚟決定幾時值得投資
