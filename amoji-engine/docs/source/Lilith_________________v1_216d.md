# Lilith 系統規格 —— Part I:眼睛錨點系統 + 微動作研究
## 「眼睛係靈魂之窗」—— 完整眼球運動科學基礎

之前嘅 PL-L/PL-R(瞳孔方向)只係一個簡化嘅二維方向值。呢份文件將佢升級做一套完整嘅
「眼球運動系統」,包含錨點目標、多層次微動作、同每種情緒嘅具體生理調變數值。

## Part 1:眼睛錨點系統(Eye Anchor / Gaze Target)

### 1.1 核心概念:眼睛唔係「望向一個方向」,而係「望住一個目標」
你提出嘅「錨點」概念,喺機械人學文獻入面已經有正式做法,叫 **attention target**(注意力目標)。
一篇 2025 年嘅人機互動論文(Mirror Eyes)明確噉設計:<cite index="177-1">系統會加入約束方程式,強迫「凝視向量」(gaze vector)必須與注意力目標相交</cite>,而唔係淨係郁去一個抽象角度。

**對你套系統嘅意義**:PL-L/PL-R 唔應該淨係一組「方向數值」,而應該係**由一個實際嘅錨點座標,反向計算出嚟嘅結果**:

```
anchor = { x, y, z }  // 目標喺三維空間(或者虛擬2D畫面)嘅座標
         可以係:對話對象嘅臉、某件物件、或者 null(冇特定目標,進入待機掃視)

PL-L, PL-R = solve_gaze_vector(eye_socket_position, anchor)
```

### 1.2 頭-眼協調(Head-Eye Coordination)——大幅度轉移要有分工
唔係任何錨點轉移都淨係郁眼球。機械人研究確認咗人類嘅做法:<cite index="181-1">當凝視角度太大,人類會轉動頭部或身體去輔助眼睛追蹤目標,因為單靠眼球轉動唔足以將目標保持喺視網膜中央區域。</cite>具體數字方面,一篇手持機械人研究發現:<cite index="179-1">眼球追蹤嘅有效工作範圍受限於一個離開目標約 27 度嘅最大角度——超過呢個範圍,單靠眼球已經唔夠用。</cite>

**建議實作規則**:
- 錨點偏移 < 27°:淨係郁眼球(PL-L/PL-R)
- 錨點偏移 27°-60°:眼球 + 頭部轉動一齊分擔
- 錨點偏移 > 60°:頭部/身體轉動做主導,眼球只做微調

### 1.3 「前庭眼反射」(VOR)——頭郁嗰陣眼要反方向補償
呢個係好重要嘅細節:<cite index="178-1">當頭部因為做手勢(例如點頭)郁嗰陣,系統會運用逆向運動學(IK)調整凝視向量,令眼睛持續追蹤住注意力目標——呢個做法模擬咗人類嘅「前庭眼反射」(vestibulo-ocular reflex)。</cite>即係話:**如果 Lilith 一路都望住用戶,就算佢點頭,個眼神都應該持續鎖定住用戶個臉,唔會因為個頭郁咗而甩開視線**——冇呢個補償,個角色會顯得好假。

### 1.4 錨點嘅四種狀態
| 錨點狀態 | 行為 |
|---|---|
| **鎖定(Locked)** | 錨點 = 對話對象,持續追蹤 + VOR 補償 |
| **游離(Idle scan)** | 錨點 = null,進入隨機慢速掃視(思考/心不在焉時用) |
| **迴避(Averted)** | 錨點刻意偏移開對話對象(尷尬/懷疑側目用——之前情緒表已經有呢啲數值,而家可以正式表述做「錨點偏移量」) |
| **追蹤(Pursuit)** | 錨點會移動(例如追蹤一件移動緊嘅物件),對應下面 3.3 嘅平滑追蹤 |

## Part 2:微動作分類學(Fixational Eye Movements)

呢個係你問「所有微動作」嘅核心答案。人眼喺「固定望住一樣嘢」嗰陣,其實從來冇真正完全靜止,
而係有三種疊加嘅微動作:

### 2.1 三種微動作
<cite index="166-1">凝視住一個目標會引發細微眼球運動,包括微掃視(microsaccades)、飄移(drifts)、同震顫(tremors)。當中微掃視係最快、幅度最大嘅一種,運動軌跡係直線;飄移係喺微掃視之間發生嘅緩慢彎曲運動;震顫就係疊加喺飄移之上、極快速同細微嘅震盪。</cite>

**具體參數**(可直接編碼):<cite index="168-1">微掃視係一種細小、不自主嘅眼球運動,喺視覺固定期間發生,持續時間通常 6-30 毫秒,幅度細過 0.1 度視角。</cite>

**功能**:<cite index="166-1">凝視固定目標期間嘅微掃視活動,對於防止視覺喪失(避免視網膜影像消退)擔當重要角色。</cite>

### 2.2 微掃視同情緒/認知嘅關係——呢個直接回答你問嘅「情緒對眼睛微動作嘅影響」
<cite index="10-1">情緒性圖片會抑制微掃視嘅發生頻率,而針對負面情緒目標嘅隱性注意力轉移,會令微掃視方向偏向同目標相反嘅方向。</cite>更精確嘅實驗結果:<cite index="11-1">參與者觀看令人不悅嘅圖像時,顯著抑制咗微掃視出現嘅頻率,並改變咗瞳孔大小;另外,針對情緒刺激嘅隱性注意力定向,誘發嘅微掃視反應會顯著偏向目標嘅反方向,反應時間仲要快。</cite>

**對你套系統嘅實際規則**:
- 遇到負面情緒觸發(憤怒/恐懼/厭惡):微掃視頻率**降低**(眼睛「定住」)
- 微掃視方向:如果有一個負面情緒來源(例如懷疑/戒備嘅對象),微掃視應該偏向該來源嘅**反方向**(呢個係一個好深層、好唔起眼但心理學上有據嘅細節)

### 2.3 平滑追蹤(Smooth Pursuit)
當錨點本身喺移動(例如追蹤緊一件移動物件或者移動緊嘅對話對象),眼球會做平滑追蹤而唔係一連串跳動——呢個同「掃視(saccade)」係完全唔同機制,建議做獨立參數:`pursuit_gain`(追蹤增益,反映追趕目標移動速度嘅緊密程度)。

### 2.4 輻輳(Vergence)——雙眼唔一定平行
當錨點好近(例如貼近臉嘅嘢),雙眼會輕微向內聚合(輻輳),唔再係平行望向遠方。建議加一個
`vergence_angle` 參數,根據錨點距離計算,近距離時 PL-L 同 PL-R 唔再對稱平行,而係雙眼各自
向內側偏一個角度。

## Part 3:每種情緒嘅眼球生理調變數值(可直接編碼)

### 3.1 瞳孔放大——有機械人臉部研究俾出具體百分比
一篇專門做「混合臉機械人」嘅研究直接量化咗呢個問題,呢個係**可以直接攞嚟用**嘅數字:
<cite index="26-1">相對於中性表情,各情緒嘅瞳孔放大百分比大致係:開心(+3% 至 +8%)、嚴肅(-2%)、憤怒(-3% 至 -5%)、恐懼(-3%)、傷心(+4%)、厭惡(+1% 至 +3%)。</cite>同一篇研究仲發現:<cite index="26-1">開心表情嘅瞳孔放大程度持續高過中性表情,而驚訝係唯一可以做到同開心相若嘅放大幅度嘅情緒;憤怒喺所有測量點入面,瞳孔尺寸都係最細嘅。</cite>

**⚠️ 留意人類生理研究同機械人設計研究有啲出入**:純人類心理生理學研究發現<cite index="19-1">厭惡同傷心先係最一致同瞳孔放大有關嘅情緒,厭惡通常係瞳孔放大最強嘅預測因子;開心嘅影響反而較弱,恐懼就係延遲反應。</cite>兩份研究出現差異好正常(人類真實生理反應 vs 為咗令機械人「睇落更加吸引人」而設計嘅參數),**建議你哋兩套數值都保留,人類寫實模式用返生理研究數字,機械人/卡通誇張模式可以參考機械人設計研究嗰組更加「討好」嘅數字**。

### 3.2 眨眼頻率——同焦慮/認知負荷掛鈎
<cite index="25-1">情緒性眨眼模式已經被研究做焦慮偵測嘅生物標記,喺人機互動框架入面應用。</cite>結合之前思考模式研究,建議規則:
- 平靜/中性:標準眨眼頻率
- 思考/深度處理:眨眼頻率**降低**(專注時人會眨少啲眼)
- 尷尬/緊張:眨眼頻率**提高**(不安時眨眼會變頻密)
- 恐懼/驚訝:短暫「凍結」(眨眼暫停),然後可能出現一連串較快嘅眨眼

### 3.3 對臉部唔同區域嘅注視時間差異
<cite index="21-1">研究發現開心同驚訝表情,人望向眼睛區域嘅時間有顯著差異,驚訝表情仲有顯著較多嘅注視次數。</cite>呢個提示緊:如果 Lilith 將來需要「望住第二個角色嘅臉」嚟判斷佢嘅情緒,唔同情緒表情會令 Lilith 自然噉將注視集中喺唔同區域(例如判斷驚訝表情時,佢自己嘅眼神都會多啲留喺對方眼睛,呢個屬於「觀察者」場景,而唔係「表演者」場景,可以留返做未來擴充)。

## Part 4:整合方案——Layer E(眼球運動子系統)

正式喺 Layer 2/3 之間,加入一個專門嘅眼球運動子系統:

```
Layer E · 眼球運動子系統
├─ 錨點管理 (Anchor Manager)
│   ├─ 當前錨點座標(對話對象 / 物件 / null)
│   ├─ 頭-眼分工判斷(<27° 眼球主導,27-60° 混合,>60° 頭部主導)
│   └─ VOR 補償(頭部郁動時反向修正凝視向量)
│
├─ 微動作生成器 (Micro-movement Generator)
│   ├─ 微掃視(頻率受情緒調變:負面情緒降頻率、偏向刺激反方向)
│   ├─ 飄移(持續嘅慢速細微漂移)
│   └─ 震顫(高頻極細微震盪,一般可以簡化做視覺雜訊,唔使精確模擬)
│
├─ 瞳孔控制器 (Pupil Controller)
│   └─ 依情緒查表(開心+3~8%、傷心+4%、憤怒-3~-5%、恐懼-3%、厭惡+1~3%、嚴肅-2%)
│
├─ 眨眼控制器 (Blink Controller)
│   └─ 頻率依認知/情緒狀態調整(思考降頻、尷尬升頻、驚恐短暫凍結)
│
└─ 高階眼球行為
    ├─ 平滑追蹤(移動中嘅錨點)
    └─ 輻輳(近距離錨點雙眼內聚)
```

### 同現有系統嘅銜接
- PL-L/PL-R 依然係最終輸出值,但而家由「錨點 + 頭部姿態」反向解算出嚟,唔再係手動填嘅方向數值
- 之前情緒表入面嘅眼神方向數值(例如思考嘅 U+R、懷疑嘅側目),而家可以重新理解做「錨點偏移量」而唔係直接嘅 PL 數值——即係「思考」情緒設定緊一個「離開對話對象、偏右上方」嘅**臨時錨點**
- Layer 3(微表情/Step-Out)嘅眼神部分,而家可以整合返 Layer E 嘅微掃視/瞳孔控制,令「先眼後口」嘅洩漏時序有更豐富嘅生理細節(例如洩漏一刻,瞳孔都應該同步出現微妙變化,唔止眼瞼/眼球方向)

## Part 5:⚠️ 更正筆記 + 「Easter Egg」敘事慣例層

### 5.1 更正:「望右上=講大話、望左上=回憶」唔係科學

呢個講法源自 NLP(神經語言程式學),曾經流行到俾警方測謊訓練都用過,但已經被正式學術研究推翻。
Wiseman、Watt 等人 2012 年發表喺 *PLoS ONE* 嘅研究(*The Eyes Don't Have It: Lie Detection and
Neuro-Linguistic Programming*)分兩部分驗證:第一部分分析真實案例(電視上呼籲尋人嘅發言者,
部分之後被 DNA/監控證據證實講大話),發現講大話同講真話嘅人,望左望右嘅頻率完全一樣;第二個
實驗俾參與者睇片憑眼球方向判斷邊個講大話,結果都測唔到任何預測力。**呢個講法唔可以寫入你套
系統嘅「科學根據」清單,亦都唔應該對客戶或者專利代理人聲稱佢有心理學實證基礎。**

呢個都市傳說**部分基礎其實係真嘅**——被問到答唔到嘅問題會傾向「望上」搜尋記憶(對應之前
「思考模式」文件嘅眼神移離研究),但 NLP 加咗「左右分邊真假」呢層完全冇實證支持嘅細節,先變成偽科學。

### 5.2 「Easter Egg」層——刻意同科學系統分離嘅文化慣例功能

雖然唔科學,但呢個講法喺流行文化入面已經深入民心——好多觀眾會不自覺噉用呢個框架去「解讀」角色。
建議做一個**完全獨立、預設關閉、清楚標籤**嘅選用功能,唔混入 Layer E 嘅正式眼球運動系統:

```
easterEggs: {
  nlpGazeConvention: {
    enabled: false,              // 預設關閉
    disclaimer: "此為流行文化慣例,非科學實證——僅供敘事/表演風格選用,不可用於真實測謊或可信度判斷",
    behavior: {
      constructing_or_evasive: { direction: "up-right", useCase: "角色刻意/劇本標記為『不可信』時的表演選擇" },
      recalling_memory: { direction: "up-left", useCase: "角色回憶過去事件時的表演選擇" }
    }
  }
}
```

**設計原則**:
1. **獨立命名空間**——放喺 `easterEggs` 底下,唔可以放入 `engine/eyeAnchorSystem.js` 嗰個正式科學根據嘅模組,避免將來被誤認做「經過驗證嘅行為」
2. **強制顯示免責聲明**——任何開發文件或者面向客戶嘅介紹,一旦提到呢個功能,必須清楚標明「文化慣例,非科學」
3. **唔可以用於任何涉及真實判斷嘅場景**——例如客服機械人唔可以用呢個「判斷用戶是否講大話」,只可以用於故事/角色扮演類場景(例如遊戲角色、虛擬主播嘅表演風格選項)
4. **命名建議**:呢類功能之後如果仲有其他「流行但唔科學」嘅慣例(例如「摸鼻代表講大話」「唔敢對視代表心虛」),都可以歸類做同一個 `easterEggs` 集合,方便管理同持續標註

### 5.3 對你商業定位嘅意義
呢個更正本身反而係你套系統嘅一個優勢展示——**你會分得清邊啲係實證科學、邊啲係流行迷思**,呢個
判斷力對於將來面對投資者/專利代理人/企業客戶嘅技術盡職審查,係一個信譽加分位,好過將所有「聽落
